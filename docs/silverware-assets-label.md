# Silverware Assets: a preview's label

Planned with the user 2026-11-14. A preview (the view `preview`, not the original nor the card) may show a label: lines of text above it and under it, each made of the file's properties the user turns on, in the order they set.

## Decided

- **Properties**: the type's icon (added the same day, the user's wish: on by default, left of the alt text; drawn as a card's, no dot after it, left out of the tooltip), the alt text (the embed's own, else the file's name: it never shows empty), the name, the size, the date changed. Each turned on or off. The date the file was created is left out until SilverBullet is probed for it (its `created` may be none or the date changed on Linux and in Docker).
- **Where**: each property is above the preview or under it, in an order of the user's; the properties on in one place are one line, `·` between them.
- **Settings**: a label for all files and one per type; a type follows all files' whole, or has its own whole (made from all files' as it is turned on). Not per property: with on, place and order, a type following all files in part would be unclear once all files' changed.
- **Default**: the icon and the alt text on, above; the others off (the name above, the size and the date under it). A label saved before the icon came gets it under the preview, off (read leniently).
- **Both alt and name on**: both shown (the user's choice), but an alt text that falls back to the name where the name is shown too is left out, so a file without alt text does not show its name twice.
- **Cards and links**: edited in the same spirit (the user's wish, the same day), each on a sample (`ui/cardeditor.ts`: a card as the page draws it, its icon, size and date shown or hidden, its name always; a sentence with a link, its icon shown or hidden), from the same parts (`ui/sample.ts`). Neither moves anything (a card's layout and a link are fixed): their settings stay as they were (`card`, `linkIcons`), not the label's model.

## Settings

`silverware.assets.labels = { default = <label>, types = { pdf = <label>, … } }`, a label `{ above = { { field = "alt", on = true }, … }, below = { … } }`. Read leniently: an unknown property dropped, one given twice kept once, one missing added under the preview, off.

## The settings window

On the **Appearance** tab (*Preview*; the dialog's tabs below), under **Label**: a pick list of All files and each type; a type's own box (off: it follows all files', the editor shows those and takes no change, saying so). The editor is a sample of a preview as the page draws it (the user's wish: to see at once how it will look): the type's icon in a box, the label's lines above and under it drawn by the page's own code and styles, of a sample file's values (`lake.jpg`, *Sunset over the lake*, 2.4 MB, today; a PDF's *Quarterly report*…), and the properties not shown a row of chips over the sample's ground (the user's wish, the same day), in the properties' own order. **One element** (the user's wish, the same day: the chips by the sample were the same thing twice): the properties shown are the label's lines of the sample themselves, each as its sample value, drawn as on the page. Pointed at, focused or chosen (a click; a tap, as a finger has no pointing), a property is outlined and a pill over it shows its name and a ×; its text is not swapped for its name (weighed with the user: a value and a name are of other widths, the line would reflow under the pointer, another property coming under it). A click chooses, not hides (a hide by a click on what reads as a result would come by mistake): × or Delete hides it, its place kept; a chip of the row clicked is shown where it was. Dragged (`shared/drag.ts`, a finger after holding it), a property moves within its line, to the other, up to the row (hidden); a chip from the row into a line (shown there). Alt+← → steps a property (past an end into the other line), Alt+↑ ↓ moves it to the other line, Esc lets it go. A line without a property is a slot saying "Drag a property here"; every place is outlined while one is dragged.

## The settings dialog (2026-11-14)

Reviewed with the label (the user's wish: easy to use). It was one long column (all files' fields, a table of six columns per type, the label under the fold). Split into tabs by what is set, each with a line on top saying what: **Files** (shown as, a click, a Shift+click: all files' row first, set apart, then each type's, "Like all files" for following), **Preview** (its size: all files', each type's folded under **Per type**, open where one has its own; its label), **Original** (width dragged, a PDF's height), **Cards & links**, **Markdown**. The dialog is as tall on every tab (it no longer jumps as tabs are switched). One set of settings behind the tabs, written once on Save (the first tab answers for the others). On a phone (`max-width: 480px`, or a touch screen at most 600 px high, as the other plugins' dialogs) it covers the whole screen, its tabs a row that scrolls sideways, what a finger presses larger, the Files tab's rows a type's name over its three choices (`settings-touch.spec.ts`).

## Drawn

- Elements of the frame (`swa-own`, `.swa-label-above` before the preview, `.swa-label-below` after it), as wide as the preview (they give the frame no width: `contain: inline-size`), one line each, cut with `…`, the whole as the tooltip.
- The size and the date come from the host a moment later (as a card's); none: left out.
- A click on a label is the preview's (its action); the "…" stays at the preview's corner (moved down by the line above).
- A preview in a grid's cell alike.

## Tests

The model (read, kept, a type's label), the label's lines (fallback, dedupe, order), the editor (drag, boxes, a type's own), the tab saving it; a UI test in SilverBullet: a preview with the default label, then one under it, its "…" at the preview's corner.

## Appearance (2026-11-14)

The user's wish: the preview's and the card's and link's settings in one tab under another name. **Appearance** (how a file looks where it is shown) holds them, picked by a switch (**Preview** | **Card** | **Link**, `segmentedControl`), one shown at a time: a preview's label (first: what is set most, on its sample) and its size; a card; a link. The tabs are now **Files**, **Appearance**, **Original** (behaviour, not looks: a width dragged, a PDF's height) and **Markdown**.

## A link's marker (2026-11-14)

The user's question: a link's icon hidden, where is its menu? A card without its icon has its "…"; a link had none, so hiding the icon took the menu away (Show as embedded, Delete, …) without a word. Weighed with the user: the icon shown on hover alone (a finger has none, its tap follows the link), a right click or a long press (hidden; a long press is the text's selection on a phone), a note only. Chosen (the user's idea): a small arrow after the link (`swa-link-marker`, an SVG chevron, not a glyph of the font), in the link's colour, faded, lit as pointed at; after the link, not before (a small mark before a word reads as a bullet or a slip); it takes more than it draws (around it, 6 px; a finger's 12 px), of the link's text a few px at most. So `linkIcons` is now the icon or the marker, never neither: the icon is a sign of the type and the menu's way in, and only the sign can be hidden. In the Link sample the marker shows in the icon's place, chosen as the rest (its name, "Menu"), with no ×.

Its look was checked on screenshots, light and dark, at rest and pointed at. The sample's property in a line of text is an `inline-block` (an `inline-flex` box set the icon by its bottom edge, on the baseline, unlike the page; a plain `inline` one could not be pointed at). The page's icon keeps `vertical-align: -0.125em` (its 1em box from just under the baseline to the capitals' height); `middle` was measured and sat it visibly lower.

## Per type (2026-11-14)

The user's wish: a type set apart from all files seen at once, and taken back to them easily. A row-per-type switch was weighed; the user chose the way of Silverware Database's properties dialog: the rows one under another (all files first, then each type, its icon), one open at a time (a click on its head; its chevron turned). A type with a label or a size of its own is marked **Own** in its head, nothing more (the user's word: that it differs is enough there; what differs is said as it is opened). Open, a row holds its label and its size (the one label editor moved into it; the size's fields, a type's empty where all files' hold, their values its placeholders); a type's label or size made its own as it is changed (the user's word: no line saying what it follows, no button to make it its own), the two taken back to all files' by one **↺ Reset to all files**, shown where the type differs. The label editor's "follows" state (shown, not changed) went with it. The `For` pick list and the folded `Per type` sizes went. Saved as before (`labels`, `previews`).

A card without its icon had its "…" beside it, outside the card, and it was cut off where the card filled its line (the user's report). It has the link's arrow now, after its name within the card (`menuMarker(doc, "card")`, shared with the link's: `swa-menu-marker`), in the Card sample too, in the icon's place, with no ×. Measured as it was found: the card was `max-width: 100%` of its content box, its padding and border 22 px past SilverBullet's frame, whose `overflow: hidden` cut its end off; it is `box-sizing: border-box` now.

## Alignment (2026-11-14)

*Moved to Silverware Layout the same day (docs/silverware-layout-align.md): the "…" menu's Align, the Original view and the defaults per type went; a file's `align` stays in its embed, Layout's entry. What follows is how it was first built.*

The user's wish: a file aligned left, centred or right, set on the file itself, the drag of its width following it; the global *Width dragged* (`anchor`) gone with the Original tab. Decided with the user: left by default (as SilverBullet draws a file: no page looks other once installed); a default for previews (all files' and a type's own, in the Preview rows beside the size) and one for originals (the new **Original** view of Appearance, with a PDF's height); a file's own from its **…** menu (**Align**, a segmented row of the shared popup menu: `PopupSegmented`), written in its embed as `{ align: center }` (none where it is its view's default); a card at the left always (no width to drag, the user's word); in a grid's cell within the cell.

`alignFor` (model/settings.ts) gives a frame's alignment, which Assets keeps and hands to Silverware Layout as the frame's anchor (`start`, `center`, `end`); **Layout alone places it** (the user's word, the same day: where a thing stands on the page is Layout's, and without Layout no file is aligned). Assets drew it first where Layout laid no width out, its own CSS beside Layout's: two places doing one thing, taken out. Layout places every widget whose provider gives an anchor, with or without a width, in a narrow pane too (`data-swl-anchor`; the host's inline box round its widget made a line's width, the margins important over SilverBullet's; a widget in a room a block of its own width); one without (a table) as it is drawn. A preview is a widget now, placed and never widened (the contract's `resizable`: no handle). Layout's contract got `end` (shared/layout.ts): a widget at the text's end grows to the left as far as the pane's left edge less half the gutter, its handle beside its left edge (a drag outwards, to the left, widens it), its guides from its right edge; in a room (a cell) each anchor within the room. Measured in SilverBullet: left at the text's start, centred in its middle, right at its right edge; a right one dragged 80 px to the left 200 → 280 px, its right edge where it was. The setting `anchor` is taken out of CONFIG as the settings are saved.

## An original's label (2026-11-14)

The user's wish: an original (the view `embed`, as SilverBullet draws a file) given a label as a preview is. Its own settings, `silverware.assets.originalLabels` (the same shape as `labels`: all files' and a type's own), none shown by default (`NO_LABEL`: every property off), so no page looks other once updated. Edited in **Appearance → Original** by the same rows as a preview's (`labelRows`, ui/mediatab.ts, one function for both: a preview's adds its size), its sample the preview's. Drawn by the same code (`labelled("embed")`, decorate.ts) above and under the original; a click on it is no action (an original has none of its own: its text alone).
