# Silverware Assets

The files a page embeds and links (prefix `swa-`, settings and Space Lua API under `silverware.assets`): each shown as the original, a preview or a card, its menu (the "…", a card's or a link's icon), a link turned into an embed and back, a file shown in a side panel or enlarged; the settings window (`Silverware Assets: Settings`: tabs Assets, Markdown). Split out of Silverware Layout 2026-11-14 ([docs/silverware-assets-split.md](../docs/silverware-assets-split.md)); its design and decisions: [docs/silverware-assets.md](../docs/silverware-assets.md). What is left before the branch's merge, and how to work: [docs/silverware-layout-assets-next.md](../docs/silverware-layout-assets-next.md). User docs: `silverware-assets.md`; the code pages `-init.md` (settings, the bridge, the command), `-api.md` (priority 50: `silverware.assets.api`, types and actions registered, `shared/assets.ts`), `-style.md`.

## Mental model

- **Silverware Layout is optional**: its API (`silverware.layout.api`, handed over by the init page) gives a medium's width by its handle (a `LayoutProvider`, as Silverware Table registers) and what its grids draw outside the editor (`shared/rendered.ts`: each file and link drawn, its place in the page). Without it, files are decorated where SilverBullet draws them, without the handle; there are no grids then.
- The code keeps the word "asset" (`shared/assets.ts`: `Asset`, `AssetType`, `AssetAction`), the plugin's name.
- **Layers** (src/isolation.test.ts): `model/` (settings, pure), `core/` (the registry, which type, view and action apply, an embed found in the text), `builtin/` (its own types and actions, through the contract alone), `ui/` (card, menus, the settings window's tabs), `decorate.ts` (`AssetDecorator` over an `AssetHost`), `host/silverbullet/` (SilverBullet's embeds and links, its platform, its markdown-as-written elements) used by `index.ts` alone.
- **Which embed a widget of the editor is** (`core/locate.ts`, SilverBullet's widget carries no position, 2.12.1): first where SilverBullet's editor says it is (`positionOf`, **SILVERBULLET-INTERNAL**: `host/silverbullet/editorposition.ts`, `client.editorView.posAtDOM`, the one exception to the rule of no SilverBullet internals, the user's choice 2026-11-14; checked against the text, the isolation test keeps it to that file, `assets.spec.ts` checks it by name; to take it out, delete that file and its one line in `host/silverbullet/assets.ts`), else by the text drawn around it (`contextOf`: the editor's lines before and after it, matched with the written ones less their marks, `closestContext`), else by the run of widgets drawn (`placeAmong`: the editor draws what is in view) and where it is in the page. Located again as a change is written (`locateNow`): another embed may have changed since. Files in a grid have their place, told (`shared/rendered.ts`).
- **Settings**: `silverware.assets.<key>` (views, actions, card, heights, anchor, linkIcons), each key its own line of Assets' own block of CONFIG (marker `-- managed-by: silverware-assets`: tables the Configuration Manager would lose); `silverware.assets.syntaxMode.*` in the Configuration Manager's.
- **Markdown as written** (`shared/syntaxmode.ts`): files hidden, a click on a link the cursor's (`data-swa-syntax-shown`, `data-swa-syntax-clicks`, `data-swa-text` on the editor's text).

## Tests

- `src/isolation.test.ts`: the layers (model, core, builtin, ui; SilverBullet only in `host/silverbullet/` and `index.ts`), no other plugin's code (Silverware Layout only through its API, `shared/layout.ts` and `shared/rendered.ts`), of Layout's marks only `data-swl-width` in the style page.
- `ui-tests/` against SilverBullet only (`helpers.ts`: a test's pages and files under `UiAssets/<test>/`, CONFIG put back): `assets.spec.ts` (files in a page and in Layout's grid, the settings window, the markdown-as-written mode), `link-touch.spec.ts` (the touch project).
