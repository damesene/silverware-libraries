## Silverware Database

Databases in the spirit of Notion (`silverware-database/`, prefix `swd-`, settings and API under `silverware.database`; on the branch `feat/database`, in development: the model, the stores (memory and pages), the core, views and places, the SilverBullet binding, the built-in views (table, list, board, calendar, timeline) and the modules' frame with the properties' dialog and the peek done): one item one page, its properties the page's frontmatter, shown by a code block `silverware-database` in table, list, board, calendar and timeline views. The plan, the probes' results, the steps and the decisions: [docs/silverware-database.md](docs/silverware-database.md) (*Steps* first). Conditional formatting, planned for a later session (the table's `conditions/` domain shared, one evaluation for every view): [docs/silverware-database-conditional-formatting.md](docs/silverware-database-conditional-formatting.md). Built as the others (a core that knows no module and no view by name, views and modules added without changing it) and apart from SilverBullet and from where a database is kept: a model in memory, `DatabaseStore` and `ViewStateStore` the core's interfaces, items by an opaque `ItemKey`, pages and frontmatter the pages store's, SilverBullet the binding's (`host/silverbullet/`), checked by folder in `isolation.test.ts`. What it shares with Silverware Table and Silverware Tags is in `shared/` (step 2, done: filter.ts, compare.ts, platform.ts; Silverware Table moved onto them); it needs no other plugin installed. Step 2b, done: **the page writer** (`shared/pages/`, see the `shared/` entry of *Layout*), the one place that knows how anything is written in a page, and Silverware Tags moved onto it, so that no plugin writes a page's text (the plan's *Decided* 18 to 25). What step 2b's review left open, each with its step (Silverware Tags' `Space` onto the platform, the writer's rule checked in the database, Tags' Playwright tests, the frontmatter codec's higher API, a plan's summary in the model's terms, nested properties): the plan's *Left open after step 2b*. Steps 3 and 4 (the model, the stores, the core, the binding) are done, each step's decisions and what it left open in the plan; steps 5 (the built-in views), 7 (the properties' dialog, before 6) 6 (the peek, a module: an item a view opens shown beside the page, `openItem`) and 8 (views and types of your own documented on the library page, its examples run by `src/docs.test.ts`; a definition may be a function given HELPERS, `views/helpers.ts`, `TYPE_HELPERS`; a custom type guarded, `domain/types/custom.ts`) done; **modules** (`core/module.ts`: a definition `{ name, label, description, settings, start(host) }`, started where `silverware.database.modules.<name>.enabled`, given a `ModuleHost` (the core's writes, reads, types, the user, its settings, `offer`/`offered`, `refreshPlaces`), giving `placeMenu` (its entries in a place's ⋯, by slot: core/placemenu.ts over shared/menuslots.ts), `placeDrawn`, `openItem` and `stop`; modules import only types from core; built-in ones in `modules/`: properties, peek). A block's element may be given back by SilverBullet for a text it was rendered for (its widget cache): drawn anew from that text once it wrote and came back (index.ts `backAfterWriting`); presses beside a block on its line are taken (`pressBeside`). The pages store reads the index and writes through the page writer only (a place's state too: the writer's `codeBlocks` part); SilverBullet tells of a page indexed before a query gives it, which the store allows for (*Step 4c* in the plan). Since then (2026-11-08/09, each a section of the plan, their decisions and reviews there): **a view's state is the core's** (core/place.ts, kept in the block as `<view>.<key>`, its keys and forms one module's, `core/statekeys.ts`): filter, sort, Group by, **Color by** and **Visible properties** (each view its own, `<view>.hiddenProperties`, or `shownProperties` for a view `properties: { hiddenByDefault: true }`: the calendar, the timeline; the schema hides nothing); a view reads them as results, `host.listing` (which items, in what order) and `host.look` (`shownProperties`, `hiddenProperties`/`setHiddenProperties`, `colorBy`/`setColorBy`, `icon(item)`, `item(item, element)`); **Apply to all views** (core/applyall.ts, pure) gives one view's part to the block's other views. **A property's key changed** follows into the views' blocks on every page (`PlaceStore`, the binding's `blockPlaces`; `placeStateRenamed`). **Deleting** an item (the peek's bin) and a whole **database** (⋯ and a command; its pages and its blocks on every page, its name typed first; `removeDatabase`, the last change of a transaction removing every item; the page writer's `codeBlocks.remove`). **Undo** keeps a transaction whose undo could not put back what only it holds (`heldBack` in core/history.ts) and keeps a page it cannot make again as `Recovered/<name>` (`DatabaseStore.recoverRemoved`). Local UI tests against SilverBullet: the local SilverBullet on port 3010 collides with the test servers' first port, so stop it or move them (`SW_SB_FIRST_PORT`).
