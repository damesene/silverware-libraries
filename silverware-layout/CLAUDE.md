# Silverware Layout

The layout of a page: its text's width (the page's own, a default for every page), widgets' widths (laid out and changed by their handle; Silverware Table, Database and Chart register theirs) and the editor's font size with font zoom (prefix `swl-`, settings and API under `silverware.layout`). The plan, the probes' results and every decision: [docs/silverware-layout.md](../docs/silverware-layout.md) (*Steps* says what is done). User docs: `silverware-layout.md`; the code pages `-init.md` (settings, the bridge, the command, the events), `-api.md` (priority 50: `silverware.layout.api`), `-style.md`. Listed in REPO.md since 1.0.0.

Columns in a page (src/grid/: an area with Layout's layers inside), its plan, decisions and what is done in its *Steps*: [docs/silverware-layout-grid.md](../docs/silverware-layout-grid.md). Embedded files are Silverware Assets' (split out 2026-11-14, [docs/silverware-assets-split.md](../docs/silverware-assets-split.md)), which uses Layout through its API alone: a provider registered (`shared/layout.ts`; `layOutAgain` as it decorates) and what the grids draw outside the editor (`silverware.layout.api.rendered`, `shared/rendered.ts`: each file and link a cell drew, its place in the page, its cell as its room; `src/grid/drawn.ts` takes them as a cell is drawn); the other way, what draws a file in a cell's field, registered by Assets: `rendered.drawEmbeds`, handed to the field by the SilverBullet host's `embeds`, an image alone without it). Layout knows no asset: an element laid out before that no provider takes any more has its width taken off (`Widgets.layOutIn`). **What is left before the branch's merge** (a fix, edge, releases, the PR) and how to work: [docs/silverware-layout-assets-next.md](../docs/silverware-layout-assets-next.md).

## Mental model

- **Responsibilities**: a widget's plugin draws its widget and keeps Silverware Layout's entries for it (`layout.*` in its own markdown) without understanding them; Silverware Layout alone gives them meaning and shows them. The contract is `shared/layout.ts` (`LayoutProvider`, `layoutOf`, `LAYOUT_VERSION`), as `shared/icons.ts` is Silverware Icons'.
- **The registry** (core/registry.ts): one provider per name, registered again it replaces (Space Lua loaded again runs the widget plugins' init pages again, and `api` is the same object: the module is imported once).
- **Any host** (src/host/page.ts): Silverware Layout asks a `PageHost` for the page (its content, editor, pane, view, guides' layer, how its text's width is shown) and marks the page itself (host/marks.ts: `data-swl-content`, `data-swl-editor`, `--swl-pane-width`, `data-swl-narrow`, `data-swl-font-size`), which its style page reads: **no code but host/silverbullet/ and no rule of the style page names SilverBullet's elements** (isolation.test.ts checks both). `app.ts` is Silverware Layout over a `PageHost` and a `LayoutStore` (settings, a page's width, this device's zoom); `index.ts` is SilverBullet's binding (its page, its store: the bridge, CONFIG, the page writer). Another host gives its own `PageHost` and store; `app.test.ts` runs the app over plain elements.
- **Widgets' widths** (host/widgets.ts, ui/handle.ts, put together by widgetlayout.ts for the app and the playground): the widget's own element gets `data-swl-width` and `--swl-width` as it is rendered (a MutationObserver on the host's content), the style page's rule sizes it (centred, at most the pane less 40 px, `--swl-pane-width`), off under `data-swl-narrow` and out of the page's flow (`data-silverware-over-window`). **Where a widget stands is Layout's** (docs/silverware-layout-align.md): the entry `align` (`left`, `center`, `right`), read and written through the provider alone like `width`, else the user's default for the widget's kind (the provider's `kinds` and `kindOf`; the dialog's Alignment tab, `silverware.layout.alignments` keyed `<provider>/<kind>`), else the kind's own, else centred (host/widgets.ts `alignOf`; the default chosen is written as none). Placed with or without a width, a narrow pane too (`data-swl-anchor`: start, centred, end; the host's inline box round it a line's width). One at the start grows to the right alone, one at the end to the left alone (its handle beside its left edge), each as far as the pane's edge less half the gutter (`widestWidth`; guides wider are none of its, the style page's rules hold it there too), a centred one both ways; in a room (a cell) each within the room. The inline box an aligned widget stands in is marked `data-swl-anchor-holder` by the code (its parent alone, only an inline one: never a list's item), not by a `:has` of the style page. A click on the handle's grip opens its menu (`showPopup`: Align, the default marked; the width taken off), after the time a double click would take (a double click takes the width off, no menu). A widget its provider says is not `resizable` (a preview), and any in a pane too narrow to lay widths out (a phone: shown only beside a widget the bar fits beside in the window, so none by one as wide as the screen), gets the grip for the menu alone (`swl-handle-menu-only`, the drag's line plainly off: faint, no accent nor growth as pointed at; a press opens it, nothing dragged), its own even in a grid. A touch in the handle's menu is not a touch beside the widget (it would close the menu before the tap). The handle, a short grey grip (lit as pointed at; the column dividers have the same grips, a thin line over the widget's height shown on the pointer: the user's choice 2026-11-14), its target 120 px at most and centred on the part of the widget in view (the host's `view`: SilverBullet's scroller; what is seen of a widget its provider's optional `seen`, a table's held header), drags (written on release), snaps (text width, the guides: `silverware.layout.guides`, px, % of the pane or `full`; a widget snapped to a % guide keeps the percent, `layout.width: 80%`, its CSS a share of `--swl-pane-width`), takes a width off by a double click; no preset button (the user's choice). While it drags, a quiet dashed line each side per guide over the editor's visible height, in the host's `guideLayer` at z-index -1 (SilverBullet's: CodeMirror's scroller, a stacking context: the lines lie under the widgets, as Confluence's); the one snapped to solid.
- **The font size** (docs/silverware-layout-font-size.md): this device's zoom (local storage, host/devicezoom.ts; Font zoom on), else the setting `fontSize`, else none (the theme's) (core/fontsize.ts). Shown by the style page's rule on the editor (marked `data-swl-editor`; SilverBullet's `#sb-main .cm-editor`) where the root has `data-swl-font-size` (SilverBullet 2.12.1 sizes it in px, no variable to set). `ui/fontzoom.ts`: Ctrl + scroll over the editor (a capture listener, not passive, the browser's zoom held back there alone), Ctrl/Cmd+0, the label at the bottom left; at the default no zoom is kept, as the browser keeps none at 100 %.
- **Grids** (columns, src/grid/, an area with Layout's layers inside: docs/silverware-layout-grid.md): `<grid …>` … `</grid>` drawn by SilverBullet's custom syntax (the init page's `syntax.define`, its renderer `renderGrid`), each cell's markdown rendered by SilverBullet (`markdownToHtml`, handed over as `renderMarkdown`), the grid read and written by `shared/markdown/grid.ts` and the page writer's `grids` part. SilverBullet hands the renderer the body alone and draws a grid anew only as its body changes: the attributes (`columns`) are read from the page's text, the grid found by its body, and set again on the grids drawn as the page is edited (`Grids.refresh`).
- **The text's width**: the page's own (`_layout.width` in its frontmatter, px a number, % a text), else the default setting, else none (the theme's); none in a pane narrower than `minPaneWidth` (core/textwidth.ts). Shown by the host (`PageHost.showTextWidth`); SilverBullet's (host/silverbullet/dom.ts) sets `--editor-width` inline on the root, important: what SilverBullet's text, top bar and notifications read, winning over a theme's `!important`.

## Layers (src/isolation.test.ts)

- `model/`: widths (px or %, read from what a page or a setting holds) and settings, pure; imports nothing outside it.
- `core/`: the registry, which text width applies, a widget's width (read, dragged, snapped, named); the model and `shared/layout.ts` alone.
- `ui/`: the Page layout dialog, the font zoom (`FontZoomHost`) and the handle (`HandleHost`: what it asks of whoever lays widgets out); the model and shared UI (dialog, controls, elements), never the host, the bridge or the page writer.
- `host/`: the page as any host has it: `PageHost` (page.ts), Silverware Layout's marks (marks.ts), the widgets laid out (widgets.ts), this device's zoom (devicezoom.ts). No SilverBullet.
- `host/silverbullet/`: SilverBullet's page (dom.ts, `silverBulletPage`), the page's `_layout` read and written through the page writer (page.ts), the writer's platform (platform.ts). Used by `index.ts` alone (and the playground, whose editor imitates SilverBullet's).
- `app.ts` ties model, core, ui and host over a `PageHost` and a `LayoutStore`; `widgetlayout.ts` the widgets and their handle (the playground's layout.ts too); `index.ts` is SilverBullet's binding; `bridge.ts` is what the init page hands over.

## Gotchas

- **The width of a page opened is handed over by the init page's Lua** (`pageLoaded(page, width)`, from `editor.getCurrentPageMeta()`), set synchronously: read from JS, each call of the bridge is a promise answered later, and the page showed at the old width for frames. The text is read as well right after (`pageOpened`), as the meta is the index's, which may lag behind a write.
- `editor:pageModified` re-reads the frontmatter after 300 ms still (a width typed by hand); not while the dialog shows a width it is setting.
- The dialog (anchored at the window's top right, the page not darkened) has these tabs: Alignment (a pick list per kind of widget the providers name, its own default marked; `ui/aligntab.ts`, saved in Silverware Layout's own block of CONFIG), Page width (This page, All pages: a slider marked with the guides, snapping to them, a number and px/%), Font (All pages' font size; This device's zoom with *Ctrl + scroll zooms here*, the setting `fontZoom.enabled`) and Guides (a row each, typed straight in, sorted only as the tab is shown, never while typing; Full width a box; Preview held, by the pointer or Space/Enter, draws the guides as typed on the page through `previewGuides`, the dialog all but gone as for a slider (`hold`); Default guides puts `DEFAULT_GUIDES` in the rows once `confirm`ed, saved on Save). The guides' lines are `ui/guidelines.ts` (`GuideLines`), the handle's drag and the Preview alike. Every row of a value is one shape (`rowOf`): its name where it holds at the left, a slider, the value typed and ↺; a row without a value of its own (`swl-dialog-follows`) has its field empty, the value it follows its placeholder and a note under it (*Uses …*); moving or typing makes it its own, ↺ takes it back (decided with the user 2026-11-13: the Default/Own and Theme/Own switches went, the tab Text width named Page width, as the guide of the text's width is). The guides are saved in Silverware Layout's own block of CONFIG (`withConfigSettings`, marker `-- managed-by: silverware-layout`): the Configuration Manager reads no table back.
- A slider of the dialog held (`slides`): the dialog `swl-dialog-sliding` (visibility hidden, its controls held `swl-dialog-held` alone visible), so what it changes is seen under it, on a phone too; let go on the window's pointerup or pointercancel. The controls held must not move as they are pressed (their ground by padding and as much negative margin): moved a few pixels between pointerdown and the browser's start of the drag, a press near the slider's edge was off it, and nothing dragged. The rows following another (This page without a width of its own, This device without a zoom) are drawn again with every change (`update`). With the dialog open, the font zoom is its *This device* row (`PageDialog.font`, `setZoom`: Ctrl + scroll anywhere, as the dialog's ground lies over the editor; kept on Save, put back on Cancel, the dialog's Ctrl + scroll box as ticked there). *This device* is a slider of this device's zoom, saved by `saveZoom` on Save: a size set there is kept even where it is the size of all pages (a row's own value, as a page's width is), while Ctrl + scroll back at the default keeps none.
- **Started again under an open dialog** (another plugin's settings saved: SilverBullet loads the configuration and Space Lua again, `init` runs again): `start` keeps the page it had, so the dialog is not taken for one over another page and closed, and what it shows is not undone.
- The dialog shows what is set at once and writes on Save; Cancel puts the page back without asking, Esc, × or a press beside it ask where changes would be lost. Taking a page's width off takes `_layout` with it where it held nothing else (else `_layout: {}` stayed).
- The bundle is about 110 kB: the page writer (shared/pages/) brings lezer's markdown parser. The writer stays the one place writing a page.
- The unit switch is `segmentedControl` (shared/controls.ts), styled by `shared/segments.css` (the menu's segmented entry's look, the same classes).

## Tests

- Unit tests: `src/**/*.test.ts` (widths, settings, the registry, which width applies, `_layout` read and written through the page writer over an editor of memory, the app over a page of plain elements and a store of memory, the layers and the names of SilverBullet kept to its host).
- `ui-tests/layout.spec.ts` runs against SilverBullet only (`--editor-width` is SilverBullet's): a test's pages under `UiLayout/<test>/`, CONFIG put back after. A page written for a test is indexed a moment after it opens: wait for its `_layout` in the index (`waitForIndexedLayout`) before following a link to it. A link followed may show one frame at the page before's width on a busy machine (`LATE_FRAMES`).
- **SilverBullet puts a widget's element into the page first and its content after** (a table widget's `span`, then its `<table>`): a widget is laid out again as content comes into it (`layOutIn` looks at the widget around an added node), else a table's width read before its metadata row was there was none.
- A widget is drawn anew after each write (a new element): the handle finds it again where it was before any press (`place`), else it would drag a detached element (width 0). Playground tests measure a widget through `box()`, which waits for the new one.
- A finger has no hover: a touch on a widget shows its handle (a passive capture listener, the tap still the widget plugin's), a touch elsewhere hides it, two taps on the bar are its double click (a browser's own dblclick after them not taken twice). On a coarse pointer the bar's `::before` widens what a finger takes. `touch.spec.ts` (the touch project, at a tablet's size: a phone's pane is under `minPaneWidth`).
- **The boxes a widget is in, within the content, let it out** (`overflow: visible` on each by `:has`): SilverBullet shows a Lua block's output (a database's place) in a box of the text's width with `overflow: auto`, which cut a widened database off.
- `silverbullet.spec.ts` checks what Silverware Layout takes of SilverBullet's page (`#sb-editor` the pane, its width given; `.cm-content` and the editor found and marked; `.cm-scroller` a stacking context the guides lie under widgets in; `--editor-width`; a widget held at the pane; the boxes between a grid's frame and the grid showing what lies outside it, its column grips' upper halves whole): a new SilverBullet changing one fails there, by name, where the playground's tests stand in for SilverBullet and would not.
- `widgets.spec.ts` runs on the playground (`layout.html`, tagged `@playground`); `layout.spec.ts` on SilverBullet, as `grid.spec.ts` (columns; a test's files, an image or a zip, written beside its pages by `space.open`'s third argument; `PIXEL_PNG` an image of one pixel). Files in a grid are tested in Silverware Assets' `ui-tests/assets.spec.ts`. A grid is drawn only once SilverBullet's custom syntax is active: `gridsDrawn` loads the page again until it is. Run them with `SW_SB_FIRST_PORT` set where a SilverBullet of your own is on 3010.
- **How SilverBullet behaves is allowed for in its host alone** (`src/host/silverbullet/behaviour.ts`, the user's rule 2026-11-14: no plugin depends on it directly): the grids ask `GridHost`'s hooks, `textForDrawing` (it draws a grid before its editor's text is the new one: the text given the body drawn, or read again as a page opens), `afterPress` (it sets its editor's selection again as a grid is drawn anew: a cell left by a press written once the press is over), `focusPage` (its editor focused again), and its editors' `historyAtWindow` (shared/editor.ts `EditorHost`). Another host answers its own or not at all; the isolation test keeps `[contenteditable` to the host too.
- **A cell edited** (src/grid/ui/celleditor.ts, grids.ts `edit`): left by Esc or Ctrl+Enter, or by a blur that a press caused (a pointerdown going on); a blur without one to nothing is a host's taking the focus as it draws a grid anew: the cell kept, the focus given back. Left by a press, it is written when the host's `afterPress` says. The cells' writes run in turn, each after its grid is drawn anew (`writeLater`, `redrawn`): a cell edited meanwhile is moved into the new drawing (`retake`, `moveTo`), only a drawing a write of ours made. `ui-tests/grid-touch.spec.ts` and the grid's "straight into another" test hold these.
- **The page's cursor kept out of a grid** (docs/silverware-layout-grid.md *The cursor kept out*): every press in a grid is the grid's, the grid takes the focus (`tabindex=-1`, src/grid/ui/view.ts); a press beside it (on its line, in the margin at its height) does nothing, as beside a table (`GridHost.pressBesideGrid`, host/silverbullet/dom.ts); the arrows over it by `src/host/silverbullet/cursor.ts`; its markdown by Alt+click or the menu's *Edit markdown*.
- **A click on a link shown as its markdown** (src/host/silverbullet/links.ts; the setting `links.clickPlacesCursor`, the Page layout dialog's Markdown tab; moved from Silverware Assets 2026-11-15, the user's choice: it is the whole page's): the caret in a link, SilverBullet shows its spans (`span.sb-wiki-link`, `span.sb-link`, the `span.sb-meta` marks beside them) and still follows it on a click (CodeMirror's `click` handler, 2.12.1): told at the press (CodeMirror draws the line anew before the click), the click stopped at the document's capture; a link drawn as a link (`a`) followed as ever, Ctrl/Cmd+click too. While the markdown is shown as written, `shared/syntaxmode.ts`' `placesCursor` with the same setting. The text pointer by the root's `data-swl-text-pointer` (the style page names no SilverBullet element).
- **A grid's menus by its handles** (docs/silverware-layout-grid-handles.md): a column's by its grip (`src/grid/ui/columngrips.ts`, at the middle of its top edge, half above; shown under the pointer, on a touch screen while the grid has the focus; hidden, it takes no press), the grid's own in the widget handle's menu after Align and Width (`LayoutProvider.menu`, shared/layout.ts: a provider's sections, the grid's provider giving `Grids.menuOf`); where no handle shows (a narrow pane, `handleHidden`), each column's menu has a *Grid…* opening the grid's own (its column's actions alone in it, *Delete column…* last). No "…" on the cells any more. Its columns are a row of choices (`LayoutMenuChoices`): Auto (`columns="auto"`, as many equal columns as fit, none under `min`; no dividers, `data-swl-fit`, kept in a narrow pane) or 2 to 8.
- **A cell's field looks as the page renders**: a task's box, a done task's text and a hashtag (`shared/editorlook.ts`: a sample rendered by the host once a page, put in the cell out of sight as the field opens, its properties read as computed, handed to the field as `EditorOptions.look`).
- **A grid drawn anew takes over the drawing it replaces** (`src/grid/takeover.ts`): the cells of the same markdown whole, and in the cell written its blocks of the same markdown, their offsets moved to where they start now; only from a grid gone from the page, drawn in a page of the same text before it. Every offset of a cell's rendering is read through `src/grid/ui/offsets.ts` (`data-pos`, an offset of 0 may be unmarked). Its lines while edited lie in the middle of its gaps, its layout as it is (the style page).
- **Dragging text** (`src/grid/drag.ts`, docs/silverware-layout-grid.md *Dragging text*): always a move; into a cell as one edit where the host writes moves (`GridHost.isPageText`, `pageSelection`, `writeMove`), out of a cell once dropped elsewhere. Where a point of a cell's rendering is in its markdown: `src/grid/ui/cellpoint.ts` (a click, a drop, a selection).
- Page markers in a frame's text mislead: a page's Linked Mentions quote the other page; tell pages by their heading.
