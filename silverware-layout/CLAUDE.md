# Silverware Layout

The layout of a page: its text's width (the page's own, a default for every page) and widgets' widths (laid out and changed by their handle; Silverware Table registers its tables, Database and Chart are next) (prefix `swl-`, settings and API under `silverware.layout`). The plan, the probes' results and every decision: [docs/silverware-layout.md](../docs/silverware-layout.md) (*Steps* says what is done). User docs: `silverware-layout.md`; the code pages `-init.md` (settings, the bridge, the command, the events), `-api.md` (priority 50: `silverware.layout.api`), `-style.md`. Version 0.1.0, not listed in REPO.md until it is usable.

## Mental model

- **Responsibilities**: a widget's plugin draws its widget and keeps Silverware Layout's entries for it (`layout.*` in its own markdown) without understanding them; Silverware Layout alone gives them meaning and shows them. The contract is `shared/layout.ts` (`LayoutProvider`, `layoutOf`, `LAYOUT_VERSION`), as `shared/icons.ts` is Silverware Icons'.
- **The registry** (core/registry.ts): one provider per name, registered again it replaces (Space Lua loaded again runs the widget plugins' init pages again, and `api` is the same object: the module is imported once).
- **Any host** (src/host/page.ts): Silverware Layout asks a `PageHost` for the page (its content, editor, pane, view, guides' layer, how its text's width is shown) and marks the page itself (host/marks.ts: `data-swl-content`, `data-swl-editor`, `--swl-pane-width`, `data-swl-narrow`, `data-swl-font-size`), which its style page reads: **no code but host/silverbullet/ and no rule of the style page names SilverBullet's elements** (isolation.test.ts checks both). `app.ts` is Silverware Layout over a `PageHost` and a `LayoutStore` (settings, a page's width, this device's zoom); `index.ts` is SilverBullet's binding (its page, its store: the bridge, CONFIG, the page writer). Another host gives its own `PageHost` and store; `app.test.ts` runs the app over plain elements.
- **Widgets' widths** (host/widgets.ts, ui/handle.ts, put together by widgetlayout.ts for the app and the playground): the widget's own element gets `data-swl-width` and `--swl-width` as it is rendered (a MutationObserver on the host's content), the style page's rule sizes it (centred, at most the pane less 40 px, `--swl-pane-width`), off under `data-swl-narrow` and out of the page's flow (`data-silverware-over-window`). The handle, a bar quiet until pointed at (as Silverware Table's +), 120 px at most and centred on the part of the widget in view (the host's `view`: SilverBullet's scroller; what is seen of a widget its provider's optional `seen`, a table's held header), drags (written on release), snaps (text width, the guides: `silverware.layout.guides`, px, % of the pane or `full`; a widget snapped to a % guide keeps the percent, `layout.width: 80%`, its CSS a share of `--swl-pane-width`), takes a width off by a double click; no preset button (the user's choice). While it drags, a quiet dashed line each side per guide over the editor's visible height, in the host's `guideLayer` at z-index -1 (SilverBullet's: CodeMirror's scroller, a stacking context: the lines lie under the widgets, as Confluence's); the one snapped to solid.
- **The font size** (docs/silverware-layout-font-size.md): this device's zoom (local storage, host/devicezoom.ts; Font zoom on), else the setting `fontSize`, else none (the theme's) (core/fontsize.ts). Shown by the style page's rule on the editor (marked `data-swl-editor`; SilverBullet's `#sb-main .cm-editor`) where the root has `data-swl-font-size` (SilverBullet 2.12.1 sizes it in px, no variable to set). `ui/fontzoom.ts`: Ctrl + scroll over the editor (a capture listener, not passive, the browser's zoom held back there alone), Ctrl/Cmd+0, the label at the bottom left; at the default no zoom is kept, as the browser keeps none at 100 %.
- **The text's width**: the page's own (`_layout.width` in its frontmatter, px a number, % a text), else the default setting, else none (the theme's); none in a pane narrower than `minPaneWidth` (core/textwidth.ts). Shown by the host (`PageHost.showTextWidth`); SilverBullet's (host/silverbullet/dom.ts) sets `--editor-width` inline on the root, important: what SilverBullet's text, top bar and notifications read, winning over a theme's `!important`.

## Layers (src/isolation.test.ts)

- `model/`: widths (px or %, read from what a page or a setting holds) and settings, pure; imports nothing outside it.
- `core/`: the registry, which text width applies, a widget's width (read, dragged, snapped, named); the model and `shared/layout.ts` alone.
- `ui/`: the Page layout dialog, the font zoom (`FontZoomHost`) and the handle (`HandleHost`: what it asks of whoever lays widgets out); the model and shared UI (dialog, controls, elements), never the host, the bridge or the page writer.
- `host/`: the page as any host has it: `PageHost` (page.ts), Silverware Layout's marks (marks.ts), the widgets laid out (widgets.ts), this device's zoom (devicezoom.ts). No SilverBullet.
- `host/silverbullet/`: SilverBullet's page (dom.ts, `silverBulletPage`), the page's `_layout` read and written through the page writer (page.ts), the writer's platform (platform.ts). Used by `index.ts` alone (and the playground, whose editor imitates SilverBullet's).
- `app.ts` ties model, core, ui and host over a `PageHost` and a `LayoutStore`; `widgetlayout.ts` the widgets and their handle (the playground's layout.ts too); `index.ts` is SilverBullet's binding; `bridge.ts` is what the init page hands over.

## Gotchas

- **The width of a page opened is handed over by the init page's Lua** (`pageLoaded(page, width)`, from `editor.getCurrentPageMeta()`), set synchronously: read from JS, each call of the bridge is a promise answered later, and the page showed at the old width for frames. The text is read as well right after (`pageOpened`), as the meta is the index's, which may lag behind a write.
- `editor:pageModified` re-reads the frontmatter after 300 ms still (a width typed by hand); not while the dialog shows a width it is setting.
- The dialog (anchored at the window's top right, the page not darkened) has two tabs: Page (this page's width, Default or Own; all pages', Theme or Own; each a slider marked with the guides, snapping to them, a number and px/%; moving or typing makes it Own) and Guides (a row each, typed straight in, sorted only as the tab is shown, never while typing; Full width a box). The guides are saved in Silverware Layout's own block of CONFIG (`withConfigSettings`, marker `-- managed-by: silverware-layout`): the Configuration Manager reads no table back.
- The dialog shows what is set at once and writes on Save; Cancel puts the page back without asking, Esc, × or a press beside it ask where changes would be lost. Taking a page's width off takes `_layout` with it where it held nothing else (else `_layout: {}` stayed).
- The bundle is about 110 kB: the page writer (shared/pages/) brings lezer's markdown parser. The writer stays the one place writing a page.
- The unit switch is `segmentedControl` (shared/controls.ts), styled by `shared/segments.css` (the menu's segmented entry's look, the same classes).

## Tests

- Unit tests: `src/**/*.test.ts` (widths, settings, the registry, which width applies, `_layout` read and written through the page writer over an editor of memory, the app over a page of plain elements and a store of memory, the layers and the names of SilverBullet kept to its host).
- `ui-tests/layout.spec.ts` runs against SilverBullet only (`--editor-width` is SilverBullet's): a test's pages under `UiLayout/<test>/`, CONFIG put back after. A page written for a test is indexed a moment after it opens: wait for its `_layout` in the index (`waitForIndexedLayout`) before following a link to it. A link followed may show one frame at the page before's width on a busy machine (`LATE_FRAMES`).
- **SilverBullet puts a widget's element into the page first and its content after** (a table widget's `span`, then its `<table>`): a widget is laid out again as content comes into it (`layOutIn` looks at the widget around an added node), else a table's width read before its metadata row was there was none.
- A widget is drawn anew after each write (a new element): the handle finds it again where it was before any press (`place`), else it would drag a detached element (width 0). Playground tests measure a widget through `box()`, which waits for the new one.
- A finger has no hover: a touch on a widget shows its handle (a passive capture listener, the tap still the widget plugin's), a touch elsewhere hides it, two taps on the bar are its double click (a browser's own dblclick after them not taken twice). On a coarse pointer the bar's `::before` widens what a finger takes. `touch.spec.ts` (the touch project, at a tablet's size: a phone's pane is under `minPaneWidth`).
- **The boxes a widget is in, within the content, let it out** (`overflow: visible` on each by `:has`): SilverBullet shows a Lua block's output (a database's place) in a box of the text's width with `overflow: auto`, which cut a widened database off.
- `silverbullet.spec.ts` checks what Silverware Layout takes of SilverBullet's page (`#sb-editor` the pane, its width given; `.cm-content` and the editor found and marked; `.cm-scroller` a stacking context the guides lie under widgets in; `--editor-width`; a widget held at the pane): a new SilverBullet changing one fails there, by name, where the playground's tests stand in for SilverBullet and would not.
- `widgets.spec.ts` runs on the playground (`layout.html`, tagged `@playground`); `layout.spec.ts` on SilverBullet.
- Page markers in a frame's text mislead: a page's Linked Mentions quote the other page; tell pages by their heading.
