# Silverware Table

Interactive markdown tables in SilverBullet. User docs: [silverware-table.md](silverware-table.md) (the library page). More notes load with their folders: `src/core/CLAUDE.md` (the core and the SilverBullet adapter, the sheet view), `src/features/CLAUDE.md` (the model modules), `src/formulas/`, `src/columntypes/`, `src/conditions/`, `src/excel/`. Plans and decisions in `docs/`: [isolation](../docs/silverware-table-isolation.md), [sheets](../docs/silverware-table-sheets.md), [views and sources](../docs/silverware-table-views-plan.md), [conditional formatting](../docs/silverware-table-conditional-formatting.md).

## Working on it

- `silverware-table.js` is the committed, minified bundle SilverBullet installs (no build there). `npm run build` before every commit; `npm run verify` fails on a stale bundle. Its exports keep their names: the Lua of the init and API pages calls them (`init`, `evaluated`, `defineFunctions`, `commandList`…). Nothing in `src/` may rely on a function's or class's name (minified).
- The pages a space installs: `silverware-table.md` (docs only; its `files:` list the rest), `silverware-table-init.md` (`config.define`, the bridge handed to `init`, events, commands), `silverware-table-api.md` (`-- priority: 50`: the `silverware.table.*` Space Lua API, before users' scripts of priority 0; public functions carry `---` doc comments, which SilverBullet's Lua completion shows), `silverware-table-style.md` (all CSS, built-in themes; tests and the playground read it).
- Tests read the library page: a built-in function or column type without its row in the Functions / Column types table fails. Compare through `asInLibraryPage` (`src/testing/librarypage.ts`): no `@mentions` in installed pages (root CLAUDE.md).
- Every setting needs a `label` and `hint` in `SETTINGS` (bridge.ts), a place in the dialog (`dialogKeys`, a test checks) and a matching `config.define` entry on the init page.
- Unit tests: jsdom, `src/testing/page.ts` (`useTablePage()` inside a describe: renders tables as SilverBullet does, turns edit mode on; select-mode tests remove the `silverware.table.editMode` key). jsdom has no layout: `viewBounds`, `isShown` see 0, menus close where a browser keeps them; `pointInsert` sets where a + shows. Logic in jsdom, interactions in Playwright.
- `ui-tests/` (Playwright, playground and real SilverBullet via `SW_TARGET`): everything that differs between the targets is in `helpers.ts` (`setPage`, `markdown`, `setOtherPage`, `setSettings`, `reload`, `notification`, `expectNavigatedTo`, `cursorLine`…). A spec never touches the playground's `#source`, its settings store or SilverBullet's client directly. Check a write on the table rendered anew (`rendersAnew`: the marked `<table>` is gone) and "nothing written" with `settled`; check state in the markdown as well as on screen. Playground-only tests are tagged `@playground`; `touch.spec.ts` runs as a phone (project "touch"); the sheet view's specs live in `ui-tests/sheet/` (a CI job of their own).
- UI checks by hand: the playground (`npm run playground`, `http://localhost:8000/`, its Benchmark panel for large tables) and a local SilverBullet with the library deployed. The user's own SilverBullet (latest release, Tiniri theme) can differ.

## The mental model

- **Layers** (docs/silverware-table-isolation.md; `src/isolation.test.ts` enforces imports and selectors):
  - `controller.ts` + `core/`: the core. Finds and enhances the tables SilverBullet rendered, routes events, the view (sort, hidden rows, pins), menus, toolbar, the cell editor, the write pipeline. **It knows no module** (no import of `features/` except the controller's own `features/metadata.ts`, no `moduleOn("…")`): it offers generic mechanisms.
  - `features/`: model modules (`Feature`, a `ModelHost`: tables by `TableKey`, cells by markdown row and column, no DOM element, no `TableHost`, no `dom.ts`). Their own UI only through what the core makes (floating panels, menus, dialogs).
  - `core/silverbullet/` + `core/silverbullet/modules/`: the adapter for SilverBullet's rendering and the modules allowed to touch the rendered DOM (`AdapterFeature`, `TableHost`): sticky, longText, largeTables, fullScreen, sheet, tableLabels, autoscroll, history, expressions, beside, popup.
  - Domains (`formulas/`, `columntypes/`, `conditions/`, `autofill/`, `pivot/`, `calculated/`, `sheet/`, `excel/`, `export/`): pure, no host, **never read or write metadata**: the module hands them data or functions (e.g. `FormulaCells`). Modules use `formulas/` only through `formulas/index.ts`.
  - `host/` (Lua sources, Lua call places): imported by `index.ts` only.
- **Modules**: `FEATURE_NAMES` in bridge.ts (note: the grips module is `handles`, views `view`; `sheet` names two features, the adapter's `Sheet` and the model's `Sheets`). `modules.ts` `featureEntries` is **the order features get events**, with the reason for each placement in comments (sticky first; autofill before selection so Esc cancels a fill; formulas before pivot, view, columnTypes; columnTypes before conditions). Always on: metadata, expressions, history, beside, customMenus, cellPopup. Off by default: `largeTables` (`MODULES_OFF_BY_DEFAULT`).
- **A module turned off is not loaded at all** (`silverware.table.modules.<name>.enabled`, read once at start; a change needs a reload). What it stored stays in the tables, unused, and the core keeps it correct (column attributes follow their column, hidden tags are kept).
- **Each module gets its own host** (`core/modulehost.ts`), carrying its identity: it never says who it is and cannot write as another. **Another module's data only through an offer**: `host.offer(api)` / `host.offered(name)` (undefined while that module is off: behave as "no such data"). Never read another module's attributes.
- **Table identity**: `TableKey`, made only by `core/tables.ts` (`TableRegister`, which matches a page's tables to keys across edits, moves, Ctrl+Z); modules hold, compare and pass keys, never build or parse one. Per-table state lives in the module's **part** for that table (`tablePartsOf` in `core/parts.ts`, `host.tablePart`/`tableParts`); no module keeps a `Map<TableKey…>` (the sheet alone, as it lays out several tables).
- **Hooks**: all optional, listed with docs in `core/feature.ts` (`Feature`, `AdapterFeature`, `ModelHost`, `TableHost`). Read it before adding one; prefer an existing generic hook.
- **Menus are built by meaning, not by place**: a row/column menu through `lineMenu(…, menu)` and its slots (`LineMenuSlots`: clipboard, edit, insert, columnType, view, look, remove; `menu.slot.custom({ name, position, priority })` for anything else, `position` by what the actions are); the cell menu by `CELL_MENU_ORDER`, header icons by `HEADER_ICON_ORDER`, toolbar names by `TOOLBAR_NAME_ORDER`. A module picks a slot by meaning, never relative to another module's entries (decided 2026-11-04). Users' and other plugins' entries: `silverware.table.defineMenuEntries` → `menus/custom.ts` via the always-on customMenus module.
- **Public API for other plugins**: `silverware.table.tables(text)` (a text's tables as data, `tabledata.ts`) and `silverware.table.onWrite(fn)` (`core/writelisteners.ts`: told the page's text after every write, its edits outside tables written in the same `replaceRange`). Silverware Chart uses both; keep them stable.
- **Custom definitions from Space Lua** (`defineFunctions`, `defineTypes`, `defineSeries`, `defineConditions`, `defineFormats`, `defineMenuEntries`, `defineSource`): JS modules of the space (`js.importFromSpace`) or Lua for sources; each load of Space Lua replaces the definitions of before (`resetDefinitions`), the old ones staying until the first new call. A mistake is a notification naming the pages whose `space-lua` blocks call that API (the index has every block while Space Lua loads), never a Lua `error` (it would stop the user's script).

## Invariants

- **Every write is one `editor.replaceRange`** (one undo step). `write(widget, change, { rowMap, columnMap, pins, focus, … })` re-reads the table from the page, applies `change`, runs the **write steps** (features' `writeStep`, then the core's `metadataAfterEdit`: column attributes follow their column, pins), formats (`autoFormat`), adds what features write elsewhere in the same edit (`otherTablesWritten`, `otherTextWritten`, `WriteOptions.also`), then writes once. `rowMap`/`columnMap`: where each old row (markdown index, header 0) or column went, `undefined` = deleted; a row nothing maps to is new. A table's writes are serialized; a write from a table not yet rendered anew writes it as the earlier writes left it (`writtenAs`/`writeTarget`). Nothing waits for SilverBullet's rendering (a table far out of view never gets one).
- **A rule that depends on the state before the whole change belongs to the core's write step**, where the old table, every step's result and the maps are together. Nested code cannot tell editing an attribute from making one.
- **Viewing never writes.** Sorting and filtering are views unless the metadata setting stores them. Out-of-date results (formulas, views, pivots, sources changed) are shown as *Recalculate* / *Out of date*, never rewritten on view.
- **The metadata setting off** (`silverware.table.metadata`): nothing new is stored. An attribute the table has may change or go, none is added (the core's own too: sort, pins); a cell's hidden tag passes only where that cell had the attribute, or a cell of the table had it with that value (calculated columns, moves), else the write step takes it off and says so (`withoutNewTagValues`). The core's own following and Remove metadata always pass.
- **Read-only cells and fixed shapes** (`Feature.readOnly`, `fixedShape`: pivots, views) are enforced at the write (`changesFixed`), whatever offered the edit; UI that offers edits asks first and offers none.
- **Metadata names are made by the core** (`metanames.ts`): `<owner>.<key>`, a column's `<owner>.-c-<column>[:n].<key>`, the core's `core.*` (`core.table` marks the metadata row; `core.name`, `core.n`, `core.cn` names). A module passes only key and value (`host.getMeta`/`setMeta`/`columnsMeta`/`getCellTag`/`withCellTag`). Never `import` meta.ts, metanames.ts, names.ts, tagvalues.ts from a module or domain.
- **Hidden tags in cells** (`<meta …>`, `tags.ts`): every tag is kept when a cell is edited, pasted over or cleared, whoever it belongs to; a feature that manages an attribute takes it (`takesTags`) and writes it itself. Write attributes only with `metaAttribute` (markdown.ts): always apostrophes, always escaping `'` `&` `\` `>` `|`. Find tags only with `metaTagPattern`/`TAG_BODY` (a tag ends at its first `>`, as SilverBullet reads it). Readers also take old double-quoted tags (before 2026-10-22).
- **Rendered tables are SilverBullet's**: Silverware Table decorates its DOM, matched to the markdown by `data-pos` and shape. Every assumption about SilverBullet's DOM lives in `dom.ts`. Features read rows through the host (`bodyRows`, `shownRows`, `cellAt`, `rowOf`), never `querySelectorAll("tr")`: rows may be out of the document (largeTables), and a row out of it is not measured (`rowNeeded` first).
- **Sorting, filtering and copying use the cell's value** (`cellValue` in dom.ts: `data-swt-value` from column types, else the shown text); sorting alone may use a look's `sortKey` (`data-swt-sort`).
- **Cell looks** (`Feature.looks` → `CellLook`: display, value, sortKey, marks `swt-<mark>`, title, vars `--swt-*` only) are merged in feature order and applied by the adapter, which skips cells whose look did not change.
- **Floating controls** (toolbar, grips, +, menus, panels) are `.swt-floating` in `body`, made by the core only (`floating`, `panel`, `floatingMenu`), so the core knows them (`isFloating`). Hide them with `display: none !important`: themes such as Tiniri set `display` on every `button` with `!important`.
- **Large tables**: after an edit SilverBullet renders the whole table anew and the browser lays it all out; that layout must be paid once per change. View hooks (`decorate`, `viewApplied`, `toolbarButtons`) touch only cells they change, read layout before writing (never interleaved), and defer measuring (the toolbar is placed in the next frame). `parseTable` caches recent tables (immutable), so re-reading `info.source` is free.
- **Settings**: `silverware.table.<setting>`, a core part's `silverware.table.<part>.<setting>` (`editor`, `expressions`), a module's `silverware.table.modules.<module>.<setting>` (one `config.set` per part; SilverBullet fills defaults). The settings dialog writes every changed value, defaults too, into the Configuration Manager's managed block of CONFIG (`shared/configpage.ts`), so Ctrl-, and the dialog show the same; a module switched needs *Save and reload*.

## Gotchas

- **Every write renders the table anew**, asynchronously; the core enhances it later. Whatever is open then (menu, selection, outlines, Shift+click anchor, cell editor, scroll position) must survive it. Rule: keep such state by table key and cell place in the markdown, restore it on the table's `enhanced`, and close it on a real change of what it was for (the grips: a menu reopens on `enhanced`, closes when the selected cells change, not when they are shown again: `selectionOf`). Most UI bugs were here. `ui-tests/rerender.spec.ts` covers it.
- **A click that reaches a table widget shows its markdown** (SilverBullet puts the cursor at the target's `data-pos`). So the controller takes presses in capture handlers, the + band takes its press on `mousedown` and swallows the following `mouseup`/`click` (`endsInsertingPress`), and `beside.ts` redirects presses right of a table or on the empty line under it.
- **A press taken** (a menu opened by a long press or tap, `host.takePress`) swallows its later mouse events until the next pointerdown (`pressTaken()`), else the click runs the menu item under the finger or follows a link. Taps are told by pointer events: Chrome fires no mouse events for a tap after a touch drag or scroll.
- **Esc during a drag that Esc cancels** (`host.drag` with `escape`) goes to no feature.
- **Typing on a selected cell** opens the editor during keydown without `preventDefault`, so the browser types the key (dead keys, AltGr as Ctrl+Alt). Ctrl+V opens the editor so the paste event lands in its field.
- The cell editor's field is `CellField` (input | textarea): add listeners through `HTMLElement`, the union loses event types.
- The cell editor knows no selection: Esc and Ctrl+Shift+arrows call `selectCells` when `selectsCells()`.
- Edit mode vs select mode is per browser (`localStorage` `silverware.table.editMode`), not a setting; without the selection module a click always edits.
- `core/touch-keyboard.ts` is a **workaround** for SilverBullet on phones (it scrolls to its editor's cursor whenever its content holds the focus, which a cell editor's field does). Keep such code there, to be removed once SilverBullet changes.

## Verified in SilverBullet

Probe pages: a test table and an inline `${(function() … end)()}` listing `query[[from index.tag "table" where page == p]]` (an inline expression needs no reload; a new `space-lua` block does). Version 2.12.1 / main unless said.

- **Column keys** (`cleanHeaderFieldName`, plugs/index/table.ts): `/[\W_]+/g → "_"`, lowercased; `\W` is ASCII, so `Množství` → `mno_stv_`. **Hashtags in a header are left out of the key** (`Price #euro` → `price`) and tag neither rows nor the page. `columns.ts` mirrors this. A name is matched as a key first, then as a header (emphasis dropped): a key may end in `_`.
- **`<meta …>` in a cell is not shown** (any position, quotes or apostrophes, with `\|`); an HTML comment is shown. **A `>` inside a value ends the tag** even in quotes, hence `&gt;`. The index stores the raw cell text, `<meta>` and `\|` included. Empty cells are indexed with an empty value. SilverBullet keeps `<meta>` attributes in the rendered DOM (themes read `themes.name` from it). `<meta>` does not change the column key.
- **`#REF!` in a cell is a hashtag** (tag `REF`, in the row's `tags`); `\#REF!` is plain text. Errors are written escaped and read in either form.
- **Hashtags render** as `<a class="hashtag sb-hashtag" data-tag-name data-ref>`.
- **What `${…}` shows**: numbers, texts, `true` inline as markdown; a list a block; a list of records (Lua tables or JS objects) a table, columns by first-seen keys; `nil` the word `nil`; a second return value not shown. Hence `evaluate` (values) and `evaluateText` (markdown) are separate. JS arrays and objects become Lua tables and `null` nil without `js.tolua`; Space Lua awaits a JS promise. `_CTX.currentPage` exists in the `${…}` itself, not in a function it calls defined on another page.
- **Which tables are in the DOM** (SilverBullet's source and CodeMirror alone, 2026-10-22): SilverBullet makes a widget for every table (none for the table holding the cursor: it shows markdown), but CodeMirror keeps in the DOM only blocks within its viewport (view ± about 1000 px) and at the selection. A table far away, even one laid over the window, is removed and made anew later. One table is always drawn whole.
- **Markdown rendered like the table widget**: `markdown.renderToDom(md)` (Space Lua only, live `${…}`, no `data-pos`) and `markdown.markdownToHtml(md, { expand = true })` (static). Links in such DOM reload the window: route clicks to `editor.navigate` yourself. From commit `1dd7556f` (2026-10-10); the release is not verified. See docs/silverware-table-sheets.md.
- **A table widget is rendered anew after every edit**; its MutationObserver callback comes before the browser lays it out (largeTables takes rows out there: 165 ms → 13 ms for 1000 rows).
- **On a phone SilverBullet pins `#sb-root` above the keyboard** (`client/lib/keyboard_viewport.ts`) and scrolls to its cursor when the keyboard or focus changes (`keyboard_bar.tsx`); it focuses its editor when a page opens.
- SilverBullet's scroller has 360 px bottom padding, which `position: sticky` leaves out (bottom-pinned rows correct for it).
- `editor.flashNotification(msg, type, { timeout = 0, actions = {…} })` stays until closed, with buttons (main; older releases ignore the options).
- Commands defined from `commandList()` by their whole names and `/<slash>` work (2026-11-03). `editor:complete` completions show as typed.
- Without `navigator.clipboard` (a page over http, a phone on the LAN) Copy must use the copy command on a selected field before anything is awaited (`shared/clipboard.ts`; the cells' formats are `src/clipboard.ts`).
- MdTableRender hides header hashtags with JS, which flickers; Silverware Table hides type hashtags with CSS.

## Decisions (and why)

- **Formulas are stored as the result plus a hidden `<meta formulas.f='=…'>`** in the cell: every renderer and the index see a value. Details: `src/formulas/CLAUDE.md`.
- **Column types are hashtags in the header** (MdTableRender's syntax): no metadata needed, the key unchanged. Details: `src/columntypes/CLAUDE.md`.
- **Custom functions, types, series and formats are JS, not Lua**: a Lua function called from JS returns a Promise once it touches SilverBullet's stdlib, and formulas and looks are synchronous.
- **Themes are CSS only** (`--swt-*` on `.sb-table-widget[data-swt-theme="<name>"]`, dark under `html[data-theme="dark"]`): the engine maps them onto SilverBullet's own table variables, so its header, striping, held header and selection follow; a variable left out falls back to the page's value captured on `html` (`--swt-sb-*`). Rules use `:is(#sb-main, html)` to match SilverBullet's weight in both SilverBullet and the playground, never `!important`. A user's theme is a space-style block found by its selector; nothing is registered. Stripes (rows, columns, none) are a setting or the table's, not the theme's. Fonts are the device's, declared without fallback (left out: inherited).
- **Select mode is the default**, as in a spreadsheet (click selects, second click / typing / Enter / F2 edits); Edit mode edits on the first click.
- **Delete twice**: Delete empties cells; on whole rows/columns already empty (hidden rows included for columns) it deletes them; a whole empty table is deleted the same way, asked only where something goes with it.
- **Paste** is refused while sorted or filtered; cells a feature computes are left (`keepsCell`); new rows get calculated columns' formulas in the write step.
- **Pinned lines show a tint, not a border**: selected/edited cells draw inset shadows a border would clash with.
- **Every + inserts only on a press on it** (it shows quiet until hovered): rows were often inserted by presses near it (2026-11-04).
- **largeTables is off by default**: it changes the look (a scrolling box) and Ctrl+F sees only rendered rows. Virtualizing against the page's own scroll was rejected: estimated heights would move the page, and CodeMirror keeps its own height map.
- **No UI framework**: elements made synchronously with `el` (shared/elements.ts), as they are measured and placed at once (docs/ui-without-framework.md).

## Deferred / open

- One core mechanism for UI state across a table rendered anew, and an explicit interaction mode (idle, editing, menu, picking, dragging) instead of features reacting to each other's events (`pointerBusy` is a start). Not done.
- Modules loaded apart (weighed 2026-10-24, set aside): most modules are on by default, so little is saved; costs an async start, and whether SilverBullet installs and `js.importFromSpace` resolves chunks is not verified.
- Recalculating only the formulas an edit affects (every write recalculates the table: the largest cost after layout). Enter without rewriting the table (batching edits). Lua functions in formulas.
- `editor.downloadFile` for the Excel file (now a link clicked in the page; SilverBullet's mobile app unverified). A parameter picker for column types. The + band found without hovering the table first. Enter after editing in select mode follows `enterKey` (a spreadsheet would only select).
- `overscroll-behavior: contain` on a table over the window (scroll may hand on to the page, which can unload the table).
- largeTables limits: Ctrl+F, column widths from the first rows shown, estimated heights of rows out of view.
- `grips.ts` and `selection.ts` are large and could be split behind their features. Before writing a helper, look in `core/`, `menu.ts` and `shared/`; when two features need the same thing it moves there, generic.
