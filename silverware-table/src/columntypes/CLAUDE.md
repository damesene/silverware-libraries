# Column types (Silverware Table)

## Layout

```
    columntypes/       the column types domain; index.ts its API
      type.ts          the shape of a type (ColumnType)
      registry.ts      which types exist (built-in and custom: `typeNamed`, `allTypes`; a custom one replaces a built-in of its name, its aliases too), the type a header's hashtag names (a name before an alias; parameters read: `readParams`), CSS patterns
      format.ts        what types share: numbers read, Intl formatters made once
      choicelists.ts   the choice type's lists: `columntypes.choice.<name>` in a table's metadata row, a JSON list of texts or a formula (`listFormula`: its leading `=`, which no JSON list starts with), a formula's values made a list by `listOfValues` (empty ones and repeats whatever their case left out, the first kept, in the result's order; the formulas' `listResult` gives them as cells show them: its `Book` reads plain cells as written where a number would lose what they show (`asWritten`: `2024 Roadmap`, `007`, `2,5`), a number calculated with the table's decimal comma, errors left out, a grid of several columns `#VALUE!`); `ListRead`, a list's values or why none; names strict (`LIST_NAME_RE`: lower case ASCII, words joined by dashes); a column of a list has an icon of its own (a type's `iconFor(params)`, generic: the module asks it for any type)
      custom.ts        custom types (the user's, from Space Lua): definitions checked (parameters, aliases), what a method gives checked, HELPERS
      builtin/         only types, one per file (stars.ts …), index.ts their list
```

### Column types (`columntypes/`, `features/columntypes.ts`)
- A type is a **hashtag in the header** (`| Price #currency-usd |`), as MdTableRender does: verified not to change the column key nor tag rows or the page, needs no metadata setting, and MdTableRender's tables work (aliases: `#euro`, `#usd`, `#int`, `#float`, `#kg`, `#km`, `#watt`, `#logical`, `#evaluation`, `#gauge`). Parameters after a dash (`#number-2`, `#stars-10`, several dash-separated, the last taking the rest: `#unit-m-s`); MdTableRender's number suffixes (`#percent10`) are not supported. A type declares them (`params`: number with bounds, a choice of words, text with a pattern, each with an optional default) and the registry reads them (`readParams`): a hashtag whose parameters do not fit is not the type's, and the type's methods get the values (`format(text, { max })`, `columnType()` types them from the declaration), never the text after the dash.
- Display only: the markdown keeps the value; the editor shows it; what a type shows is a text, a link or a meter (`{ text, meter }`: the adapter draws a bar filled to the share with the text in a box in the page's colors over it, `swt-meter`; `#progress`), so the model side makes no element; sort/filter/copy use it (`sortValue` where the text does not sort, e.g. check marks). Invalid values show red with the reason; saving one is allowed and announced.
- The type is changed in the column menu (*Type*: a row of icons as *Filter*, the type's icon opens the list in the same dropdown, a back arrow before its title; the × removes it); editing a header shows and changes only the name, the type hashtag is kept.
- Built-in types live one per file in `columntypes/builtin/` (only types there); a test requires each type's syntax and description in the library page's Column types table. Each has an `icon` (`lineIcon` from `icons.ts`), shown after the column's name in the header and in the Type menu; the menu shows a type's syntax and description in a bubble beside it (`MenuDetail` in `menu.ts`), not a native tooltip.
- **Choices** (`#choice-<name>`, decided with the user 2026-11-03): a list of values per column is a column type, not a constraint module of its own (a validation module, Excel's Data Validation for any type, would be worth it only for constraints on numbers or dates). The list is in the metadata row by name (`columntypes.choice.<name>`, a JSON list: values with spaces, `|` or commas, room for a color per value later), the header names it; a fixed prefix, not a bare `#status`, so the CSS hiding type hashtags stays generic and no list's name clashes with a type's. One name, no aliases (`#select`, `#enum` would only raise which to use). Names strict, without diacritics. A value not in the list is marked, saved as typed; matched whatever its case; sorted in the list's order. `#choice` without a list, or a list the table lacks, checks nothing and offers the column's values. A list no column takes is not deleted by itself: it stays in the Type menu, deleted there; one columns take may be deleted too, asked first, those columns then without a type. Later: a color per value, Excel's Data Validation, filters offering every listed value.
- **A choice list made by a formula** (decided 2026-11-05/06, docs/silverware-table-views-plan.md, *A choice list made by a formula* and *Step 5: decided*): `columntypes.choice.projects='=@projects'`, the header `#choice-projects` as for any list; a list from Space Lua is a source's formula, never found by a header's name alone, so the table says where its values come from. Calculated as the column shows (the formulas' offer `list`: in none of the table's cells, its own table read as its own, no cycle), never written; formulas off, a source or page not read, an error or several columns: the column checks nothing, said in its type icon's title and in the dialog. Its formula follows the tables of the page it reads (renamed, columns renamed or moved) as a cell's does, in the same edit (`HeldFormulas`); a source is renamed by no edit, another page's tables are followed nowhere. In the Type menu under Choice as any list, its formula in the hint.
- **Custom series** (AutoFill, `silverware.table.defineSeries`) are JS as custom functions are, the same API block and replacing on a reload of Space Lua; a definition is data (`words`, a list to go round, `alone: false` for words also used otherwise) or a series (`match`); tried before the built-in ones, as a user's words are meant to win (Q1 … Q4 round, not Q5). Nothing is rechecked when they change: a fill reads them when it starts.
- **Custom column types** are JS as custom functions are (`silverware.table.defineTypes`, the same priority-50 API block, the same replacing of definitions when Space Lua loads again, a mistake a notification), in the built-in types' form: they declare `params` and get their values, a name replacing a built-in type (in its place in the Type menu, its aliases gone with it), a type's own name before another's alias. A method that throws or gives the wrong kind of value (custom.ts checks what it gives) marks the cell `swt-type-invalid` with `#tag failed: …` (the column types module's `attempt`, around every call of a type's method), never breaking the table. Tables are decorated with the types when they render: SilverBullet loads Space Lua before it opens a page (and renders the editor anew after a reload of Space Lua), so the types are there; a change of definitions refreshes the CSS hiding type hashtags (`tablesChanged`), not cells already shown.
