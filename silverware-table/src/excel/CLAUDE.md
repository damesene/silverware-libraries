
### Excel (`excel/`, `features/excel.ts`)
- Its own module beside `export` (CSV): it has its own settings and grows its own code; both use `src/export/` (what a table gives), neither the other. Excel knows the formulas (their public API: the parsed tree, `totalRows`, references), the formulas know nothing of Excel: how each function is written in Excel is a table in `excel/functions.ts` by name, and a test there requires every built-in function in `SAME_IN_EXCEL` or `EXCEL_FUNCTIONS`, so a new function needs a decision. A function in neither (a custom one without a template) is written as its value.
- Formulas go into the .xlsx file only: pasted as text, Excel reads a formula in its UI's language (a Czech Excel wants SUMA and ;) and does not shift references to where it is pasted; a file keeps formulas in English, locale-independent. Copy for Excel copies values, typed with Excel's HTML attributes (x:num, x:bool, mso-number-format; "\@" keeps text text, so 1-2 is no date).
- The file has every row in the markdown's order (formulas refer to rows by place), the header at row 1, so A1 of a formula is Excel's A2. The sheet's cells are an Excel table (`xl/tables/table1.xml`, decided 2026-10-24): named as the table (`excelTableName`, else Table1), its columns as its header names them (`excelColumnNames`: unique, not empty), its last row its totals row where that is the table's only total row (`totalsRowFormula`, a text `totalsRowLabel`), a calculated column's `calculatedColumnFormula` (a row added in Excel gets it), none for a table without rows (Excel's needs one). Column references are the table's (`Table1[Qty]`, Excel's totals row out of its rows; `Table1[[#This Row],[Qty]]`, the file's form of `[@Qty]`; `[@[a]:[b]]` as `Table1[[#This Row],[A]:[B]]`; names with `[ ] # '` escaped by `'`), but in the totals row, which has no This Row (cells there), and `[qty]` with a total row elsewhere: one run of the column's rows without total rows (else the formula is its value); operators on ranges are array formulas (`t="array"`) so Excels before 365 calculate them. Results are written with the formulas (a reader that does not calculate shows them; their number formats come from Silverware Table's results: a date's result is a date) and `fullCalcOnLoad`. Functions newer than Excel 2007 are written with `_xlfn.` (else #NAME?). TEXT is written as its value: Excel reads its format codes in its own language.
- Verified by opening generated files with Excel (16.0, English UI) through COM: the file opens without repair, XLOOKUP / TEXTJOIN (array) / CEILING.MATH / EDATE / DATEDIF / WORKDAY calculate, dates, times ([h]:mm), percentages, logical values and errors show as written; and Copy for Excel from the playground in Chrome (Playwright, headed) pasted into Excel keeps its attributes (Chrome does not strip x:num nor mso-number-format) and gives numbers (12,99 € as 12.99) and text as meant. The Excel table (2026-10-24, the same way): opened without repair as a table of its name, range, filter and totals row; `SUM([Qty])` in the totals row, `[@Qty]*[@[Price €]]` and `SUM(Table1[@[Qty]:[Qty2]])` calculated; a row added in Excel (ListRows.Add) got the calculated columns' formulas; column names with `'` and `#` (`[@[Bob''s]]`, `[@[C'#]]`) read. Not verified: Excel in another language, the download in SilverBullet's mobile app.
- What would break the file is never written: Excel refuses to open a whole file for one formula it cannot read (a wrong number of arguments, `SUM()`: verified), so a call outside its function's minArgs/maxArgs, an empty template or a range as the result is the cell's value, listed. A cell's text becomes a number only when nothing written is lost (`PLAIN_NUMBER_RE` in values.ts: `007`, a phone number, `3 kg`, more than 15 digits stay text). Templates are put in parentheses, their arguments that are operations too. The dialog groups formulas alike (a calculated column is one entry, its cells a range) and shows at most 50.
