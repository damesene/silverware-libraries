# Silverware Table: the model modules

Each file is one module (a `Feature` against `ModelHost`, no DOM of the rendering: `src/isolation.test.ts`), its test beside it. Its storage key is its name in `FEATURE_NAMES` (bridge.ts). Rules shared by all modules are in `silverware-table/CLAUDE.md`; the formulas, column types, conditions and Excel domains have their own CLAUDE.md in their folders, read them when touching `formulas.ts`, `views.ts`, `pivot.ts`, `columntypes.ts`, `choicesdialog.ts`, `conditions.ts` or `excel.ts`.

## Per module: what the code does not say

- **formulas** (`formulas.ts`, `functiondialog.ts`, `resultview.ts`): calculates its tables, views and pivots in the write step and the tables referring to the one written in the same edit (`otherTablesWritten`), formulas written outside tables too (`otherTextWritten`). Which modules it asks for calculated tables is a list by name (`CALCULATING`), as for held formulas (`HOLDING`): a new kind is one more name. While the completion list shows it takes ↑ ↓ Tab Esc; Enter is never the list's (saves as typed, as in Excel). The Functions dialog is a dialog, not a panel by the cell: it needs room. Show result is calculated when asked, never on viewing.
- **pageLinks**: reads other pages formulas (and pivots' sources) refer to, again for each write that recalculates a table reading them and when SilverBullet indexes that page. Off or not read yet: such formulas keep their stored results (`unread`), they do not become errors.
- **sources**: the space's sources (`silverware.table.defineSource`, Lua functions run from `host/sources.ts`) as tables; a change counts `version` and calls `tablesChanged` (nothing written: Recalculate / Out of date shown).
- **view** (`views.ts`, registered as `view`: attributes `view.formula`, `view.headers`) and **pivot**: tables whose body is calculated; the formulas module calculates them through their `CalculatedOffer`, so a write recalculates sources, views and readers in one edit and in order. Their body is `readOnly`, their shape `fixedShape`; a press on a cell opens their settings (`editRefused`). Renamed headers are kept by column id (`view.headers`, `pivot.headers`), as the core follows attributes by place, which calculated columns are not. A pivot's totals are re-pinned on every write (`withPins`). A pivot reading another page is not written by that page's edits nor follows its renames (as formulas of other pages). Plans: docs/silverware-table-views-plan.md.
- **sheet** (`sheets.ts`, the model side of the sheet module, same name): moving a table onto a sheet by typing its name, the sheet's data (`sheet.width.*`) handed to whichever table becomes first in the page in the same edit (`handovers`), others' `at` moved when a table grows (`refusesWrite` where the layout overlaps already). The rest is in `src/core/CLAUDE.md`.
- **names** (`names.ts`): names of tables, columns, rows, cells are the core's (`core.name`, `core.n`, `core.cn`), this module is the naming UI. A table name two tables of a page share (typed in markdown) is shown `attention` and announced once per name and page visit with a notification that stays (`timeout: 0`); formulas use the first.
- **metadata**: the controller's own (always on, a page command too); Remove metadata strips the metadata row and every hidden tag, naming their owners from the attribute names (`metadataOwners`, modules turned off too). It removes formulas (results stay) and ends a stored sort.
- **lazy**: held edits written together after `silverware.table.modules.lazy.delay` ms with no editor open; every other write of the table takes them along (`pendingEdits`). Leaving the page writes them **into its file** (`pageLoaded`, `bridge.readPage`/`writePage`), never into the editor, which already shows the next page. One flush per table at a time (`flushing`). Ctrl+Z with cells held writes them and undoes that write.
- **paste** (`paste.ts`, formats in `src/clipboard.ts`, parsing in `src/paste.ts`): Ctrl+X cuts only within the same table, unchanged in shape, while the cells still hold their text; sorted or filtered a cut is a copy. A move takes the text and the tags features manage (a formula); other tags (names) stay at both ends. Menu Paste reads the clipboard (`readText`), disabled without the Clipboard API, and where `clipboard-read` is granted (Chrome) while it holds no text, read again on focus, visibilitychange and pointerdown.
- **selection**: select / edit mode, keys on a selection, Ctrl+C, Delete twice, moving cells by their edge or Move to…, touch handles (shown only after a touch, `html[data-swt-pointer="touch"]`). A tap on a selection of several opens its menu, told by pointer events (mouse events after a tap may not come). With the paste module off it offers Copy itself.
- **autofill**: before selection in the event order, so Esc during a fill cancels it and the selection stays. Not on a table sorted or filtered (`rearranged`). The double click arrives as `mouseDown` with `detail` 2, as the controller keeps dblclick from tables. On touch the fill handle is hidden and *AutoFill to…* picks the last cell with the next press (as Google Sheets' app). Cells another feature claims (formulas, `fillCell`) are copied with references moved, the rest follows a series (`src/autofill/`; custom series tried first, a user's words winning over built-in ones).
- **grips** (module name `handles`): menus in the order every menu keeps (clipboard bar, Clear, Insert, Duplicate, Move and Pin, Type / Sort / Filter / Align / Conditional formatting, Delete). A menu closes when the selected cells change other than by its own line selection, and reopens on its table's `enhanced` after a write (`menuAgain`). Selected whole lines move together when the grip is on one of them.
- **widths**: a drag moves the edge between two columns, the table's width kept (`movedEdge`: the nearest column on the side the edge moves into gives, down to what its header needs, then the next); widths are those measured at the press changed by the pointer's move, never measured again (a scrollbar coming or going would feed back). On release every column's width is stored with the width of the table's box then (`widths.box`): the stored pixels are of that box, never of another measure (the table's own width, later, builds on it). With every column sized the adapter lays the table out by a colgroup (`ColumnWidths`: each column its share of the sum, the table `sum / box` of its box now, down to a floor), so a drag's frame styles no cell and full screen or another window shows the same shares; with some, their cells are styled as before. Double-click / *Fit to content* moves the edge to fit the column's text (`fittedWidths`, measured on the action only). Columns added or deleted keep every column sized in the same write (`writeStep` → `widthsAfterEdit`). No handle on the last column (the table's edge). On a grid of a feature's (`addressFrame`, the sheet) it sets the grid's column alone instead, the last one too, a double-click automatic. The handle is inside its cell (past the edge the table clips it); off for coarse pointers; a press on it saves an open cell editor first. Decisions: docs/silverware-table-column-resize.md.
- **filters**: stored as `filters.-c-<column>.condition` only with the metadata setting; the syntax is `shared/filter.ts` (shared with Silverware Database).
- **columnTypes** / **choices**: see `src/columntypes/CLAUDE.md`. A choice list made by a formula is calculated as the column shows, never written. The Choices dialog takes a source as a formula (`=@projects`): a separate source picker was rejected as writing nothing a formula cannot (2026-11-06).
- **conditions**: see `src/conditions/CLAUDE.md`. The dialog previews in the table only while the dialog is put aside (`peeked`), taken back unless saved: repainting a 2000 × 10 table on every change stalled about 750 ms (2026-11-04). One preview at a time.
- **themes**: sets `data-swt-theme` / `data-swt-stripes` on the widget in `tableAdded` from the rendered `<meta themes.name>`, so a table rendered anew keeps its look before it is enhanced. Native (no theme) has no attribute.
- **excel**: user functions' templates come from `silverware.table.modules.excel.functions` (an object read through `bridge.getConfig`, not a dialog setting). See `src/excel/CLAUDE.md`.
- **export**: Copy as CSV (rows as shown) and Copy as Markdown (no hidden tags, no metadata row); `src/export/table.ts` is shared with excel; neither module uses the other.
- **customMenus**: always on, after the modules: entries of `silverware.table.defineMenuEntries` (`src/menus/custom.ts`), given the line and its table as data (`tableData`, what `silverware.table.tables` gives). A failing definition is said once.
